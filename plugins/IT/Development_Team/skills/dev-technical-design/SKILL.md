# Technical Design Draft

Turn supplied requirements and system context into a concise technical design document.

- Organize around problem, goals and non-goals, proposed approach, data and API changes, alternatives, and rollout.
- Call out risks, dependencies, migration or backward-compatibility concerns, and how the change will be tested.
- Preserve supplied constraints and list unknowns as open questions instead of inventing system details.
